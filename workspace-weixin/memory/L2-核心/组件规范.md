## 一、组件设计原则

### 1. 单一职责
一个组件只做一件事

```
✅ 好设计
├── ImageCropper/    ← 只管裁剪
├── KnowledgeTag/     ← 只管知识点标签展示
└── QuestionCard/     ← 只管错题卡片展示

❌ 差设计
└── BigCard/         ← 什么都装，太大了
```

### 2. 层层嵌套
大组件由小组件组成

```
WrongbookList           ← 列表容器
├── QuestionCard        ← 单条错题卡片
│   ├── KnowledgeTag   ← 标签组件
│   └── AnswerBox      ← 答案折叠组件
└── EmptyState         ← 空状态组件
```

### 3.  Props down, Events up
数据往下传，事件往上抛

```
父组件 → (props) → 子组件：传数据
父组件 ← (events) ← 子组件：收事件
```

## 二、组件定义规范

### 1. 标准组件结构
```javascript
Component({
  // 1. 开放属性（外部传入）
  properties: {
    // 简单类型
    title: { type: String, value: '' },
    // 复杂类型
    items: { type: Array, value: [] },
    // 带observer
    value: {
      type: String,
      value: '',
      observer: function(newVal, oldVal) {
        console.log('value changed:', newVal)
      }
    }
  },

  // 2. 内部状态（组件私有）
  data: {
    localState: 'init'
  },

  // 3. 方法（按功能分组）
  methods: {
    onTap() {
      // 触发事件给父组件
      this.triggerEvent('customevent', { data: 'xxx' })
    }
  },

  // 4. 外部样式类
  externalClasses: ['my-class'],

  // 5. 组件生命周期
  lifetimes: {
    created() { console.log('组件创建') },
    attached() { console.log('组件挂载') },
    ready() { console.log('组件渲染完成') },
    detached() { console.log('组件卸载') }
  }
})
```

### 2. 组件json配置
```json
{
  "component": true,
  "usingComponents": {
    "knowledge-tag": "/components/KnowledgeTag/KnowledgeTag"
  }
}
```

### 3. 组件标签写法
```xml
<!-- 使用 -->
<knowledge-tag 
  knowledge="{{item.knowledge}}"
  bind:customevent="onKnowledgeTap"
/>
```

## 三、Behavior 规范

### 1. 何时用 Behavior
- 多个组件有共同逻辑/数据
- 逻辑相对独立，可复用

### 2. 抽离为 Behavior 的场景
```javascript
// 场景1：表单组件都需要数据校验
const formBehavior = Behavior({
  data: { errors: {} },
  methods: {
    validate() { ... }
  }
})

// 场景2：列表项都需要选中和hover效果
const selectableBehavior = Behavior({
  data: { selected: false },
  methods: {
    onSelect() { this.setData({ selected: true }) }
  }
})
```

### 3. Behavior 冲突处理
```javascript
// 组件中使用多个 Behavior 时
Component({
  behaviors: [behaviorA, behaviorB]
})

// data 冲突：后面覆盖前面
// methods 冲突：先执行 behaviorA，再执行组件自己
// lifetimes：Behavior 先执行，组件后执行
```

## 四、Slot 规范

### 1. 默认 slot
```xml
<!-- 组件模板 -->
<view class="container">
  <view class="header">标题</view>
  <slot></slot>  <!-- 插入内容在这里 -->
  <view class="footer">底部</view>
</view>

<!-- 使用 -->
<my-component>
  <text>这里是插入的内容</text>
</my-component>
```

### 2. 命名 slot
```xml
<!-- 组件模板 -->
<view class="container">
  <slot name="header"></slot>
  <slot name="content"></slot>
  <slot name="footer"></slot>
</view>

<!-- 使用 -->
<my-component>
  <text slot="header">标题</text>
  <text slot="content">内容</text>
  <text slot="footer">底部</text>
</my-component>
```

### 3. slot 的条件渲染
```xml
<!-- 用 wx:if 控制是否渲染 slot -->
<view class="container">
  <slot name="header" wx:if="{{showHeader}}"></slot>
  <slot></slot>
</view>
```

## 五、组件间通信

### 1. 父→子：props
```xml
<!-- 父组件 -->
<child-component 
  value="{{parentValue}}"
  items="{{parentItems}}"
/>

<!-- 子组件 properties -->
properties: {
  value: { type: String, value: '' },
  items: { type: Array, value: [] }
}
```

### 2. 子→父：events
```javascript
// 子组件触发
this.triggerEvent('myevent', {
  value: 'data to pass',
  index: 1
})

// 父组件监听
<child-component bind:myevent="onChildEvent"/>

// 父组件处理
onChildEvent(e) {
  const { value, index } = e.detail
}
```

### 3. 父组件调用子组件方法
```javascript
// 给子组件加 id
<child-component id="myChild" />

// 父组件获取组件实例
const child = this.selectComponent('#myChild')

// 调用子组件方法
child.someMethod()
```

### 4. 跨代通信（Bus模式）
```javascript
// eventBus.js
const eventBus = {}

eventBus.on = function(event, callback) {
  if (!eventBus.listeners) eventBus.listeners = {}
  if (!eventBus.listeners[event]) eventBus.listeners[event] = []
  eventBus.listeners[event].push(callback)
}

eventBus.emit = function(event, data) {
  const callbacks = eventBus.listeners[event] || []
  callbacks.forEach(cb => cb(data))
}

eventBus.off = function(event, callback) {
  // 取消订阅
}

module.exports = eventBus
```

## 六、组件样式规范

### 1. 样式隔离
```json
// 组件json
{
  "component": true,
  "styleIsolation": "isolated"  // 默认，隔离
  // "styleIsolation": "shared"   // 共享（慎用）
}
```

### 2. 外部样式类
```javascript
Component({
  externalClasses: ['my-class', 'my-theme']
})

// 组件内使用
<view class="my-class my-theme">...</view>

// 父组件传入
<child-component my-class="custom-class" />
```

### 3. 组件样式优先级
```
外部样式类 < 组件内部样式 < 内联 style
```

## 八、组件性能规范

### 1. 减少 setData
```javascript
// ❌ 错误：频繁 setData
onScroll(e) {
  this.setData({ scrollTop: e.scrollTop })
}

// ✅ 正确：节流
let lastScroll = 0
onScroll(e) {
  const now = Date.now()
  if (now - lastScroll < 50) return
  lastScroll = now
  this.setData({ scrollTop: e.scrollTop })
}
```

### 2. 使用 Component 代替 Page
- 页面中用到的业务组件，用 `Component()` 定义
- 可以使用 `relations` 建立关联

### 3. 懒加载组件
```json
// app.json 或页面 json
{
  "usingComponents": {
    "lazy-component": "/components/LazyComponent/LazyComponent"
  }
}
```

## 九、组件测试自检

| 检查项 | 通过标准 |
|--------|----------|
| 单一职责 | 一个组件只做一件事 |
| Props规范 | 属性名清晰，有类型和默认值 |
| 事件规范 | 事件名用 kebab-case |
| 样式隔离 | 不影响外部，也不被外部影响 |
| 生命周期 | created/attached/ready/detached 正确处理 |
| 资源清理 | detached 中清理定时器、取消请求 |
