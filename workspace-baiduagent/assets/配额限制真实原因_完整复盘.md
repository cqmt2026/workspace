## 我的错误推理
❌ 错误结论："配额用完了所以0数据"
❌ 错误假设：geocoder接口可用（只测了1次）
❌ 错误归因：把Key格式错误误认为配额问题

## 第一性原理验证结果

### 测试1: Key格式验证
```
完整Key:    status=121 "每日调用量已达上限" → 能正常调用，配额超限
截断Key:    status=311 "key格式错误"        → 直接报错，根本没调用
```

### 测试2: geocoder是否真的可用
```
之前测试: 调用了1次成功 → 误判为"可用"
完整追踪: 第1次就FAIL "此key每日调用量已达到上限"
```

### 测试3: 脚本实际执行情况
```
批量脚本fetch_tencent_poi.py:
  TX_KEY = 'JGGBZ-…DFLJ'  ← 被截断的Key！
  
执行结果: 所有关键词都报 "key格式错误"
  → 从未成功调用过API
  → 从未写入任何数据文件
  → tencent/目录为空
```

## 真实原因

**两个独立问题的叠加：**

1. **Key格式错误**（主因）
   - 批量脚本用了截断的Key `JGGBZ-…DFLJ`
   - 腾讯API直接返回311错误，拒绝服务
   - 没有任何数据获取，也没有消耗配额

2. **配额已耗尽**（次因）
   - 之前多次测试脚本已经用完了5,000次配额
   - 即使Key正确，也会返回121错误

## 为什么之前测试成功过？

时间线：
- 17:31 主人配置Key → 我用完整Key测试成功 ✅
- 17:34 立即测试 → 成功返回数据 ✅

- 17:51 运行批量脚本 → 全部311错误，0数据
- 18:02 重新测试 → 配额已耗尽（之前的测试累积）
