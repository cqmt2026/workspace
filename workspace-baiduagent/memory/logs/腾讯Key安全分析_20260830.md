## 风险评估

### 🔴 高危场景
1. **代码仓库泄漏** → 如果工作区被commit到git/私有仓库，Key完全暴露
2. **文件被意外分享** → 如通过微信/邮件发送脚本或配置给他人
3. **多用户环境** → 其他用户可读取这些文件

### 🟡 中危场景
1. **本地服务器** → 仅本机用户可读，风险较低
2. **权限隔离** → 文件权限设置正确时风险可控

## 建议方案

### 方案A：环境变量（推荐）
```python
import os
TX_KEY = os.environ.get('TX_MAP_KEY', '')
```
- 优点：安全、标准做法、不侵入代码
- 缺点：首次配置稍麻烦

### 方案B：加密配置文件
- 使用Python的cryptography库加密存储Key
- 优点：安全性高
- 缺点：实现复杂、需要额外的密钥管理

### 方案C：密钥管理服务
- 使用OpenClaw的配置管理功能
- 优点：集成度高、统一配置
- 缺点：需要OpenClaw支持

### 方案D：保持现状（低风险）
- 如果确定文件不外泄、用户唯一
- 风险：依赖人为谨慎，非技术性保障
