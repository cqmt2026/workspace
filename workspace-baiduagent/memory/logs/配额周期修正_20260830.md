# 配额监测逻辑修正 - 2026-08-30

## 一、各平台配额周期差异

| 平台 | 配额周期 | 日配额 | 月配额 | 监测频率 |
|------|---------|--------|--------|---------|
| **高德** | 按月计算 | - | 30万/月 | ❌ 无需每日测试 |
| **百度** | 按日重置 | 5万/天 | - | ✅ 每日必须测试 |
| **腾讯** | 按日重置 | 5千/天 | - | ✅ 每日必须测试 |

## 二、高德配额特性

### 正确理解
- **不是每日配额，是月度累计配额**
- 30万次/月 = 平均1万/天，但可灵活使用
- 月初重置，月末清零
- 今日耗尽不代表明天不能用（只要月累计不超）

### 监测策略
- ❌ 不需要每天测试（浪费调用）
- ✅ 只需在怀疑超限时测试一次
- ✅ 建议在月初、月中各查一次
- ✅ 当百度/腾讯耗尽时，可优先用高德补抓

### 今日实测结果
```
status=0, info=USER_DAILY_QUERY_OVER_LIMIT, infocode=10044
```
**解读**：这是"日调用超限"，不是"月配额超限"。高德有日限（可能1万次/天），但没有耗尽月配额。

## 三、百度/腾讯配额特性

### 正确理解
- **严格按日重置**，今日0点清空
- 百度：5万/天，腾讯：5千/天
- 今日耗尽 = 必须等明日0点
- 每日早上9点前必须测试，确认是否恢复

### 监测策略
- ✅ 每日09:00必须测试（早间计划自动执行）
- ✅ 配额恢复后立即开始补抓
- ✅ 耗尽时记录时间，计算剩余等待时间

## 四、 corrected 执行逻辑

### 每日工作流（修正版）
```
09:00  测试百度配额（每日必须）
       测试腾讯配额（每日必须）
       高德只测一次（怀疑超限时）

09:30  根据配额状态决定抓取策略：
       - 百度可用 → 优先用百度补抓
       - 腾讯可用 → 用腾讯补漏
       - 高德可用 → 高德主力抓取
       - 全耗尽 → 等待，不测试
```

### 配额耗尽后的正确做法
- ❌ 不要反复测试（浪费调用）
- ✅ 记录耗尽时间，等待自然恢复
- ✅ 百度/腾讯：等明日0点
- ✅ 高德：可能是日限，等明日或调整策略

## 五、今日教训

1. **误解高德配额周期** → 导致错误判断"高德已耗尽"
2. **没有区分日/月配额** → 浪费测试调用
3. **未及时更新核心文档** → 方法论错误延续
