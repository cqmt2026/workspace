```python
def _kde_2d(x, y, points, bandwidth=1.0):
    """绾痭umpy 2D KDE锛屼笉渚濊禆scipy"""
    n = len(points)
    if n == 0:
        return np.zeros_like(x)
    px = np.array([p[0] for p in points])
    py = np.array([p[1] for p in points])
    result = np.zeros_like(x)
    for i in range(n):
        dx = (x - px[i]) / bandwidth
        dy = (y - py[i]) / bandwidth
        result += np.exp(-0.5 * (dx**2 + dy**2))
    return result / (n * 2 * np.pi * bandwidth**2)
```

## 九、HyperFrames v3 动画升级陷阱（2026-08-22）

### 9.1 Python .format() 与大括号转义
现象：KeyError: N+1 — Python的str.format()把JS注释里的花括号当成格式化变量
根因：HTML模板中的f-string和.format()冲突
解决方案：JS注释中的花括号避免写成表达式形式；模板中所有占位符必须唯一且在.format()参数中存在
状态：已解决

### 9.2 heavy overlay 导致渲染性能问题
现象：lint警告composition_heavy_overlay_count_high — 37个元素有filter:blur
根因：每个scene都有.dof-blur类（带filter:blur），9个scene叠加
解决方案：去掉particle的filter:blur、去掉backdrop-filter；DoF改为CSS var驱动；只模糊最近3个背景层
状态：已解决

### 9.3 audio标签阻塞渲染
现象：audio_processing_failed -> render blocked
根因：audio标签引用不存在的assets/audio.mp3
解决方案：注释掉audio标签，配音在pipeline配音生成步骤后注入
状态：已解决

### 9.4 visibility kill的lint误报
现象：lint报scene_layer_missing_visibility_kill
根因：lint在t=0静态分析，但visibility kill在timeline动态位置才触发
解决方案：lint局限，实际渲染正常
状态：lint误报，无实际影响

### 9.5 重叠tween修复
现象：overlapping_gsap_tweens — scene2被开场转场和区1转场同时操作
根因：两个tween对同一元素同一属性在同一时间段操作
解决方案：开场转场只做scene1退出，scene2入场统一由区1转场处理；加overwrite:auto
状态：已解决

### 9.6 Python .format()与JS模板字符串${}冲突（v4新增）
现象：ValueError: Single '}' encountered in format string
根因：HTML模板中的JS模板字符串`${x}`里的`}`被Python .format()误解析为格式占位符的闭合括号
解决方案：用%%VAR%%占位符格式替代{}，用replace()逐个替换；或将${改为$${再format()后还原
状态：已解决

## 十七、HyperFrames 视频背景渲染陷阱（2026-08-28）

### 17.1 根因：多视频同时解码导致 drawElement 截图死锁
**现象：** HF render 固定卡在特定帧（如 185 帧 / 6.17秒），报错：
`Sequential drawElement capture stalled: no frame progress for 60000ms`

**根因（已验证）：**
- index.html 中多个 `<video autoplay>` 同时解码
- Intel HD 520 核显（1.7GB 显存）无法承受 6 路 1080p 视频同时解码 + GSAP seek 截图
- 崩溃点不固定，取决于 GSAP 动画时间点（视频 seek 时 GPU 负载峰值）

**对照实验（确证）：**
| 配置 | 结果 |
|------|------|
| 无视频背景（纯文字+数字动画） | ✅ 成功 |
| 3视频 + 3静态图 | ✅ 成功 |
| **6视频**（原始配置） | ❌ 卡 185 帧（drawElement 模式）|
| 6视频（截图模式） | ✅ 成功，但速度较慢 |

**解决方案（二选一）：**
1. **降低视频路数**：把重复场景的视频换成静态图（最多保留 3 路视频）
   - 效果：速度快，画质好，推荐
2. **用截图模式渲染**：`--experimental-fast-capture=false`
   - 效果：能跑完，但速度较慢（6视频版 4m20s vs 3视频版 2m34s）

### 17.2 GSAP scale/blur 变换触发截图死锁
**现象：** 场景切换时 GSAP 动画使用 `scale` 或 `filter: blur()` 导致浏览器截图卡死

**已验证的触发组合：**
- `scale: 0.5` → `scale: 1`（淡入时放大）
- `filter: blur(15px)`（场景转场模糊效果）
- 上述变换 + 视频背景同时播放 = 高概率死锁

**解决方案：**
- 移除所有 `scale` 变换，只保留 `opacity` 淡入淡出
- 移除所有 `filter: blur()` 效果
- 若需缩放效果，用 `transform: translateZ(0)` 强制硬件加速（不推荐，稳定性未知）

### 17.3 环境依赖
| 组件 | 版本要求 | 说明 |
|------|---------|------|
| ffmpeg/ffprobe | ≥ 8.1.2 | essentials 版即可，需支持 `-print_format` |
| HyperFrames CLI | ≥ 0.8.17 | 旧版 0.8.10 有兼容性问题 |
| 系统 ffmpeg 路径 | C:\ffmpeg-bin\ | 替换为完整版 |


### 17.4 Pixabay 素材关键帧密度问题
**现象：** 渲染时报警告 `Video "bg-0" has sparse keyframes (max interval: 3s)`

**解决方案：** 重编码素材视频
```bash
ffmpeg -i input.mp4 -vf scale=-1:1080 -c:v libx264 -r 30 -g 30 -keyint_min 30 -bf 0 -preset fast -crf 23 -movflags +faststart -c:a copy output.mp4
```
- `-g 30`：关键帧间隔 30 帧（1秒）
- `-bf 0`：禁用 B 帧，改善 seek 性能

### 17.5 渲染命令（推荐配置）
```bash
# 方式一：drawElement 模式（快，但可能有稳定性问题）

# 方式二：截图模式（慢，但稳定，适合含多视频的复杂项目）
npx hyperframes render --quality standard --experimental-fast-capture=false -o output.mp4
```
