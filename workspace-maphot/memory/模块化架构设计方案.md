# 模块化架构设计方案

> 目标：每个模块独立运行，接口数据标准化，增删模块不影响整体

---

## 一、当前问题

| 问题 | 现状 | 影响 |
|------|------|------|
| 数据格式不统一 | 地图模块要`{name, data1, rank}`，脚本模块要`{name, rank, data1, data2, tag, desc}` | 每次选题切换要手动改数据格式 |
| 模块耦合 | `ScriptGenerator` 硬编码了`PromptBuilder→LLM→Validator`链 | 换脚本生成方式要改多处 |
| 地图形式不可扩展 | `draw_rank_map` / `draw_province_map` 两个方法硬编码 | 新增剖面图要加新方法 |
| 配色硬编码 | `province_map_drawer.py` 颜色写在`__init__` | 换主题要改代码 |

---

## 二、架构设计

```
┌─────────────────────────────────────────────────────────┐
│                    pipeline.py (流水线编排)              │
│  输入：选题 → 输出：MP4视频                             │
│  职责：调用各模块，传递标准化数据                        │
└─────────────────────────────────────────────────────────┘
        │              │              │              │
        ▼              ▼              ▼              ▼
┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐
│ 选题模块  │  │ 脚本模块  │  │ 地图模块  │  │ 合成模块  │
│TopicMgr  │  │ScriptMgr  │  │MapMgr     │  │MediaMgr   │
└───────────┘  └───────────┘  └───────────┘  └───────────┘
        │              │              │              │
        ▼              ▼              ▼              ▼
   TopicResult   ScriptResult    MapResult       VideoResult
   (标准化)     (标准化)        (标准化)         (标准化)
```

**核心原则：** 每个模块只通过标准化的 `Result` 数据交换信息，模块内部实现可变，接口不变。

## 四、模块接口定义

### 4.1 选题模块 TopicMgr

```python
class TopicMgr:
    def collect(self) -> List[TopicResult]:     # 采集选题
    def analyze(self, topic: TopicResult) -> TopicResult:  # 分析选题基因
    def match(self, topic: TopicResult) -> TopicResult:    # 匹配矩阵决策
```

**输入：** 选题原始数据
**输出：** TopicResult（含选题基因+推荐方案）

### 4.2 脚本模块 ScriptMgr

```python
class ScriptMgr:
    def generate(self, topic: TopicResult) -> ScriptResult:
    def save(self, script: ScriptResult) -> str:
```

**输入：** TopicResult
**输出：** ScriptResult（标准化JSON）

### 4.3 地图模块 MapMgr

```python
class MapMgr:
    # 工厂方法：根据地图形式选择绘制器
```

**输入：** Segment + 风格名
**输出：** MapResult

## 五、核心优势

| 优势 | 说明 |
|------|------|
| **模块独立** | 换脚本生成方式（如从LLM改为模板拼接），只改ScriptMgr内部 |
| **接口统一** | 所有模块用标准化Result，数据格式固定，不重复转换 |
| **易于扩展** | 新增地图形式：注册新Drawer + 实现标准化接口即可 |
| **易于测试** | 每个模块可以独立测试（传入标准化数据，检查输出） |
| **流水线解耦** | pipeline.py只负责编排，不关心模块内部实现 |
