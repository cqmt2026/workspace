## 📌 核心规则

### 1. 唯一正式版本

| 项目 | 规则 |
|------|------|
| **正式版本** | V14.0（当前最新） |
| **版本路径** | `stock-tools/` |
| **讨论基准** | 只调取 V14.0 及后续迭代版本 |
| **旧版本处理** | 归档到 `stock-tools/archive/` |
| **自动识别** | 讨论时自动进入最新正式版本 |

---

### 2. 自动版本识别

**触发条件**: 用户讨论股票系统相关话题

**执行流程**:
```
1. 检查 MEMORY.md → 获取最新正式版本号
2. 检查 stock-tools/ → 确认版本文件存在
3. 自动加载最新版本 → 忽略 archive/旧版本
4. 如用户明确要求旧版本 → 需指定版本号
```

**示例**:
- 用户说"股票系统" → 自动进入 V14.0
- 用户说"查看 V13" → 才进入 archive/V13/

---

### 3. 自动状态检查

**触发条件**: 每次进入系统时

**执行流程**:
```
1. 系统状态检查
   - 核心文件完整性（16 个 Python）
   - 版本确认（最新正式版本）
   - 最后修改时间

2. 前一日工作任务回顾
   - 读取 memory/{昨日}.md
   - 列出工作任务及完成度
   - 标记未完成事项

3. 当日任务计划
   - 定时任务检查（早盘/尾盘/回测/报告）
   - 标注优先级

4. 新任务自动衔接
   - 读取相关上下文文件
   - 继承未完成工作
   - 保持连续性
```

## 📋 版本迭代流程

```
新功能/优化 → 开发分支 → 严格测试 → 老板确认 → 合并到 V14.0 → 版本号 +1
```

**测试要求**:
- [ ] 功能测试（100% 通过）
- [ ] 向后兼容性测试（不破坏现有功能）
- [ ] 人工审核（老板确认）
- [ ] 文档更新（README/变更日志）
