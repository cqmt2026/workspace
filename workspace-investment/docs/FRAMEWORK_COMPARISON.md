## 核心缺失模块

### 必须有的（没有就不能叫量化框架）

| 模块 | 我们的状态 | 说明 |
|------|-----------|------|
| **回测引擎** | ❌ 无统一回测框架 | 每个策略自己写回测代码，没有标准的事件循环、订单管理、账户管理 |
| **策略编写接口** | ❌ 无标准接口 | 没有统一的策略基类/接口，每个策略格式不同 |
| **资金管理** | ❌ 无 | 没有仓位计算、风险预算、凯利公式等 |
| **绩效分析** | ⚠️ 基础统计 | 只有胜率/均值，没有夏普、卡玛、信息比、最大回撤、Alpha/Beta |

### 最好有的

| 模块 | 我们的状态 | 说明 |
|------|-----------|------|
| **因子库** | ❌ 无 | 没有统一的因子定义、计算、缓存机制 |
| **参数优化** | ❌ 无 | 没有网格搜索、随机搜索、贝叶斯优化 |
| **过拟合检测** | ❌ 无 | 没有交叉验证、滚动回测、夏普比率衰减检验 |
| **数据管理** | ⚠️ 基础 | 没有数据版本管理、自动更新、异常检测 |

## 我们的架构 = 脚本集合，不是框架

```
我们的现状：

workspace-investment/
├── scripts/        ← 40+个独立脚本，互相调用但无统一接口
├── experimental/   ← 实验代码，和正式代码分离
├── quant_ml/       ← ML训练，独立于策略
├── data/           ← 缓存和配置文件
└── out_data/       ← 分析结果输出

每个脚本 = 独立入口，没有统一的：
  - 数据接口（有的从DB读，有的从API读，有的从文件读）
  - 策略接口（有的用函数，有的用类，有的直接写逻辑）
  - 回测接口（每个策略自己实现回测逻辑）
  - 日志接口（有的print，有的写文件，有的推送微信）
```

# 聚宽策略示例 — 标准接口

**我们有统一的策略接口吗？** 没有。每个脚本自己从头写。

## 如果要补成框架，最少需要什么

### 核心（缺了就不能叫框架）

1. **回测引擎** — 事件循环 + 订单管理 + 账户管理 + 滑点/手续费
2. **策略基类** — 统一的 `buy/sell/cancel` 接口
3. **数据统一接口** — 所有策略通过同一接口获取数据

### 重要

4. **绩效分析模块** — 夏普/回撤/Alpha/Beta/信息比
5. **参数优化器** — 网格/随机搜索
6. **资金管理模块** — 凯利/固定比例/风险平价

### 加分

7. **因子计算引擎** — 统一因子定义、计算、缓存
8. **过拟合检测** — 交叉验证、滚动回测
9. **可视化面板** — 收益曲线、回撤曲线

---

## 建议

**当前状态是"脚本集合"，不是"量化框架"。** 要升级为框架，最少需要补回测引擎+策略基类+数据统一接口这3个核心模块。

**但问题在于：在补框架之前，我们连能稳定赚钱的策略都没有。** 没有策略的框架是空壳。

**我的建议：先集中精力找一个真正能赚钱的策略逻辑，再围绕它搭框架。** 而不是先搭框架再找策略——那样会浪费时间。
