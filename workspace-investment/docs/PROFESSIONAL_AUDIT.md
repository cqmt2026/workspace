# 专业量化机构级审查报告

> 模拟幻方/九坤/明汯架构师视角
> 审查对象：AliceQuant v4.0
> 时间：2026-07-05

---

## 审查方法

专业量化机构的架构师拿到一个框架设计文档，会问5个问题：

1. **数据可信吗？** — 数据源是否稳定？数据质量如何保证？回测能复现吗？
2. **策略可靠吗？** — 策略逻辑是否清晰？过拟合风险多大？鲁棒性如何？
3. **回测真实吗？** — 回测是否模拟了真实交易环境？滑点/手续费/冲击成本是否合理？
4. **执行可落地吗？** — 信号能变成订单吗？订单能成交吗？风控能挡住黑天鹅吗？
5. **系统可维护吗？** — 出了问题能排查吗？新人能上手吗？能持续迭代吗？

下面逐项审查。

## 第一轮审查：数据可信吗？

### 审查项1.1：数据源

| 标准 | 现状 | 判定 |
|------|------|------|
| 有稳定的主力数据源 | 腾讯API（免费，不稳定） | ❌ 不可靠 |
| 有备用数据源自动切换 | 有（efinance/akshare） | ✅ 但切换逻辑未细化 |
| 数据源延迟可知 | 未设计 | ❌ |
| 数据源有健康监控 | 未设计 | ❌ |

**问题**：腾讯API作为主力数据源不可靠。专业机构会使用万得/Choice等付费数据源，或者至少用聚宽/米筐的数据接口。免费API随时可能变更或下线。

**建议**：增加数据源健康监控，每日检查数据源可用性和延迟；考虑接入聚宽/米筐的数据API（虽然收费但稳定）。

### 审查项1.2：数据完整性

| 标准 | 现状 | 判定 |
|------|------|------|
| 全市场股票覆盖 | 有 | ✅ |
| 历史数据长度 | 2019年起 | ⚠️ 对于5年均线计算不够 |
| 退市/ST股票数据 | 有ST状态 | ✅ |
| 新股数据 | 未明确 | ❌ |
| 指数数据 | 未明确 | ❌ |
| 财务数据 | API有但未评估质量 | ❌ 未知 |

**问题1**：历史数据只到2019年。对于需要60日均线+120日均线的策略，需要至少2年数据预热。**实际上需要从2017年开始**。

**问题2**：财务数据质量未知。akshare和efinance的财务数据有多少缺失？季度数据是否完整？这些需要先评估。

**问题3**：缺少指数数据。基准对比（沪深300/中证500）需要指数数据，现在没有。

### 审查项1.3：数据版本管理

| 标准 | 现状 | 判定 |
|------|------|------|
| 每次回测绑定数据版本 | 已设计 | ✅ |
| 数据变更可追溯 | 已设计 | ✅ |
| 版本间数据差异可比较 | 已设计 | ✅ |

**判定**：通过。这部分在v4.0中已修复。

### 数据可信度评分：60/100
**短板**：数据源不可靠、财务数据质量未知、缺少指数数据。

## 第三轮审查：回测真实吗？

### 审查项3.1：回测环境真实性

| 标准 | 现状 | 判定 |
|------|------|------|
| 滑点模型 | 固定/比例/VWAP/流动性/市场冲击 | ✅ 全面 |
| 手续费模型 | 佣金/印花税/过户费/规费/最低5元 | ✅ 全面 |
| 涨跌停限制 | 有 | ✅ |
| T+1限制 | 有 | ✅ |
| 停牌处理 | 有 | ✅ |
| 新股限制 | 有 | ✅ |
| 熔断处理 | 有 | ✅ |
| **成交量限制** | **未设计** | ❌ |

**问题**：缺少**成交量限制**。回测中如果策略买入了超过当日成交量的股票，在现实中是不可能成交的。专业机构的回测会限制每只股票的买入量不超过当日成交量的某个比例（比如10%）。

### 审查项3.2：过拟合检测

| 标准 | 现状 | 判定 |
|------|------|------|
| 交叉验证 | 有（时间序列/滚动/K折） | ✅ |
| 夏普衰减检验 | 有 | ✅ |
| 参数敏感性 | 有 | ✅ |
| 随机策略检验 | 有 | ✅ |
| 多重比较修正 | 有 | ✅ |
| 鲁棒性检验 | 有 | ✅ |
| **样本外滚动回测** | **未设计** | ❌ |

**问题**：缺少**样本外滚动回测**（Walk-Forward Analysis）。这是专业机构最常用的过拟合检测方法——把数据分成N段，每段用前M段训练、后1段测试，最后综合N次测试结果。现在只有K折交叉验证，但时间序列数据不适合随机打乱的K折。

### 审查项3.3：回测结果解读

| 标准 | 现状 | 判定 |
|------|------|------|
| 收益指标 | 全面 | ✅ |
| 风险指标 | 全面 | ✅ |
| 风险调整收益 | 全面 | ✅ |
| 交易统计 | 全面 | ✅ |
| 归因分析 | 有（Brinson） | ✅ |
| 基准对比 | 有 | ✅ |
| **置信区间** | **未设计** | ❌ |

**问题**：缺少**统计显著性检验**。回测的夏普比率是1.5，但这个结果是否统计显著？标准误是多少？置信区间是多少？专业机构会给出**夏普比率的标准误和置信区间**，让使用者知道这个结果不是运气。

### 回测真实度评分：70/100
**短板**：成交量限制、Walk-Forward分析、统计显著性检验。

## 第四轮审查：执行可落地吗？

### 审查项4.1：订单执行

| 标准 | 现状 | 判定 |
|------|------|------|
| 市价单/限价单 | 有 | ✅ |
| 订单拆分 | 有 | ✅ |
| 算法交易 | VWAP/TWAP/冰山 | ✅ |
| **订单优先级** | **未设计** | ❌ |
| **订单时效性** | **未设计** | ❌ |

**问题1**：没有**订单优先级**。如果同时有多个订单（比如策略在14:50同时发出5只股票的买入信号），执行顺序是什么？按信号强度？按市值？按仓位？需要明确。

**问题2**：没有**订单时效性**。限价单如果在收盘前没成交，是撤单还是留到第二天？专业机构的订单都有时效性设置（当日有效/永久有效）。

### 审查项4.2：风控

| 标准 | 现状 | 判定 |
|------|------|------|
| 交易前风控 | 全面（10项） | ✅ |
| 交易中风控 | 全面（4项） | ✅ |
| 持仓风控 | 全面（6项） | ✅ |
| **黑名单机制** | **有但太简单** | ⚠️ |
| **白名单机制** | **未设计** | ❌ |
| **行业集中度** | **有但未细化** | ⚠️ |

**问题1**：黑名单只说了"自定义"，但没说清楚是永久黑名单还是临时黑名单。专业机构有**多维黑名单**：永久（退市股）、临时（财务造假调查中）、行业（政策打压行业）。

**问题2**：缺少**白名单**。有些策略只允许在特定股票池内交易（比如沪深300成分股、特定行业）。现在没有这个机制。

**问题3**：行业集中度只有30%一个硬性限制，但没有考虑**行业相关性**——如果同时持有房地产和银行，虽然行业不同但高度相关，实际集中度风险比30%高。需要行业相关性调整。

### 审查项4.3：实盘接入

| 标准 | 现状 | 判定 |
|------|------|------|
| 券商API统一接口 | 预留 | ⚠️ |
| 算法交易 | 有 | ✅ |
| **实盘风控** | **有但太简单** | ❌ |

**问题**：实盘风控只写了"日限额/单笔限额/人工确认"，太简单。专业机构的实盘风控至少包括：
- 每日交易次数限制
- 每日交易金额限制
- 单只股票净买入限制
- 日内回转限制
- 券商端风控（防止券商风控触发）
- 人工确认环节（大额交易需要人工确认）

### 执行可落地评分：55/100
**短板**：订单优先级/时效性、多维黑名单、白名单、行业相关性风控、实盘风控。

## 第五轮审查：系统可维护吗？

### 审查项5.1：监控

| 标准 | 现状 | 判定 |
|------|------|------|
| 绩效监控 | 全面 | ✅ |
| 风险监控 | 全面 | ✅ |
| 系统监控 | 全面 | ✅ |
| 数据监控 | 有 | ✅ |
| **因子IC监控** | **已设计** | ✅ |
| **模型退化监控** | **已设计** | ✅ |
| **策略漂移监控** | **未设计** | ❌ |

**问题**：缺少**策略漂移监控**。如果策略在某个时间段突然表现异常（胜率从60%掉到40%），需要能检测到并告警。专业机构会监控策略的**滚动绩效指标**，如果滚动N日的夏普/胜率/盈亏比出现显著下降，自动告警。

### 审查项5.2：告警

| 标准 | 现状 | 判定 |
|------|------|------|
| 告警规则 | 有（回撤/策略/数据/系统） | ✅ |
| 告警级别 | 有（4级） | ✅ |
| 告警推送 | 有（微信/邮件） | ✅ |
| **告警升级** | **有但未细化** | ⚠️ |
| **告警抑制** | **未设计** | ❌ |

**问题1**：告警升级只说"长时间未处理升级"，但没说升级规则。专业机构有明确的升级机制——比如WARNING 30分钟未处理→ALERT，ALERT 15分钟未处理→CRITICAL+电话通知。

**问题2**：缺少**告警抑制**。如果某个告警在短时间内频繁触发（比如风控连续拒绝订单），不应该每次都推送，而是合并成一条告警。否则告警轰炸会导致真正重要的告警被淹没。

### 审查项5.3：运维

| 标准 | 现状 | 判定 |
|------|------|------|
| 日志 | 有（结构化日志） | ✅ |
| 配置管理 | 有（热更新） | ✅ |
| **系统自愈** | **未设计** | ❌ |
| **容灾** | **未设计** | ❌ |
| **备份** | **未设计** | ❌ |

**问题1**：缺少**系统自愈**。如果某个Cron任务连续失败3次，系统应该自动重启它。如果数据源不可用，系统应该自动切换到备用源。现在没有这个机制。

**问题2**：缺少**容灾和备份**。如果硬盘坏了，数据丢了怎么办？如果系统崩溃了，多久能恢复？专业机构有数据备份策略和系统恢复预案。

### 系统可维护评分：60/100
**短板**：策略漂移监控、告警抑制/升级、系统自愈、容灾备份。

## 最终结论

**v4.0 在架构层面是专业的（7层架构、标准化接口、模块化），但在工程细节上还有11个短板。其中5个是致命级别的。** 

专业机构不会容忍回测结果没有统计显著性检验——因为你无法判断策略是真的有效还是运气好。也不会容忍没有成交量限制——因为回测中买到超过市场容量的量，结果就是虚高的。

**最关键的1个短板：Walk-Forward分析缺失。** 这是专业机构最核心的过拟合检测方法。没有它，你的策略优化结果可能是"在历史数据上找到的噪声模式"，而不是真实的规律。

要不要现在把v4.0更新到v4.1，修掉这5个致命问题？
