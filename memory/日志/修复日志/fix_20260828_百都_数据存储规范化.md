## 问题描述

### 问题1：数据文件命名混乱
每次抓取任务都生成不同命名的文件：
- `kq_list_chongqing_20260828_v2.csv`
- `kq_list_chongqing_20260828_v3.csv`
- `kq_list_chongqing_20260828_v4.csv`
- `kq_list_amap_20260828.csv`
- `kq_list_amap_20260828_v2.csv`

### 问题2：无标准存储目录
文件散落在`data/`根目录，无分类管理。

### 问题3：字段不规范
不同来源数据字段不一致（有的有经纬度，有的没有）。

## 根因分析

1. **无事前规范**：接到任务时直接执行，未先制定存储规范
2. **缺乏意识**：未意识到数据资产需要标准化管理
3. **临时思维**：把数据抓取当作一次性任务，而非持续能力建设

## 修复方案

### 1. 建立目录结构
```
workspace-baiduagent/data/
├── master/                    # 权威数据（合并去重后的最终版）
│   └── kq_list_chongqing_latest.csv
├── source/                    # 原始数据（按来源）
│   ├── amap/
│   ├── weijkw/
│   └── gxq/
├── temp/                      # 临时文件（可定期清理）
└── README.md                  # 数据字典说明
```

### 2. 统一命名规则
- 权威数据：`{行业缩写}_list_{城市}_latest.csv`
- 源数据：`{行业}_{来源}_{日期}.csv`
- 行业缩写：kq=口腔, zs=装修, jp=教培, cw=宠物, ym=医美

### 3. 统一字段规范
所有数据统一字段：
- 区域、机构名称、地址、电话、机构类别、经度、纬度、数据来源、抓取时间

### 4. 数据合并流程
1. 各来源数据存入source/
2. 读取所有源数据
3. 按(名称,地址)去重，高德优先
4. 写入master/latest
5. 旧latest归档为v{n}
