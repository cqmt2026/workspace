# 修复日志：P0-读取率监控 last_read_at 全空

**日期**: 2026-09-09
**子系统**: 主系统/P0
**严重度**: 低

## 问题描述
P0-读取率监控 cron 任务运行时，所有笔记的 `last_read_at` 字段均为空，`read_count` 全部为0。监控报告无实际意义。

## 根因
`p0_read_tracking.py` 的 `scan_and_update_read_counts()` 函数仅从 Obsidian 笔记的 frontmatter 中**读取**已有的 `read_count` 和 `last_read_at` 字段，但没有任何机制在笔记被打开/编辑时自动更新这些字段。

这导致：
1. 只有手动添加了这些字段的笔记才有数据
2. 即使运行扫描，也只是静态快照，无法追踪实际阅读行为
3. 所有计数保持初始值0，无法反映真实使用频率

## 修复方案
这是设计层面的局限，非bug。当前实现定位是"存在性检查"而非真正的阅读追踪。

如需启用实际追踪，有两个方向：
1. **手动触发**：每次对话涉及笔记读取时，显式调用更新函数
2. **文件钩子**：在 Obsidian 配置文件中添加事件监听，编辑笔记时自动递增计数器

当前版本保持不变，作为定期检查笔记frontmatter完整性的工具使用。
