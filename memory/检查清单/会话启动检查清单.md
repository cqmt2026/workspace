# 会话启动检查清单

**版本**: V1.0  
**适用**: 每次新会话启动

---

## 📝 标准流程

### 【步骤 1: 读取核心文档】
**必须按顺序读取**:

1. **SOUL.md** (人格定位)
   - 位置：`workspace/SOUL.md`
   - 用时：~30 秒
   - 确认：我是谁？我的定位？

2. **USER.md** (主人信息)
   - 位置：`workspace/USER.md`
   - 用时：~15 秒
   - 确认：主人是谁？偏好是什么？

3. **核心规则卡片** (10 条铁律) ⭐ **新增**
   - 位置：`workspace/核心规则卡片.md`
   - 用时：~60 秒
   - 确认：今天必须遵守的规则

4. **MEMORY.md** (核心记忆)
   - 位置：`workspace/MEMORY.md`
   - 用时：~60 秒
   - 确认：红线规则/操作规范/系统状态

---

### 【步骤 2: 读取 L1 日志】
**读取最近日期的 L1 日志**:

- 位置：`workspace/memory/日志/YYYY-MM-DD.md`
- 提取：
  - [ ] **待完成任务** - 继续执行
  - [ ] **系统状态** - 验证组件正常
  - [ ] **中断记录** - 如有则告知主人

**检查系统状态**:
- [ ] Gateway 是否运行？
- [ ] Memory 插件是否启用？
- [ ] 有无失败/卡顿的会话？

---

### 【步骤 3: 检查 Token 状态】
**运行 session_status**:
```bash
openclaw session_status
```

**检查**:
- [ ] Context 使用率：< 80% ✅
- [ ] Token 消耗：正常 ✅
- [ ] 成本：$0.00 ✅

**如超过 80%**:
- [ ] 立即触发 L1 完整更新
- [ ] 告知主人："Token 接近上限，请/new 继续"

---

### 【步骤 4: 检查后台进程】
**列出运行中的进程**:
```bash
process action=list
```

**检查**:
- [ ] 有无失败的会话？
- [ ] 有无卡顿的任务？
- [ ] 需要清理的进程？

---

### 【步骤 5: 确认今日待办】
**从 L1 提取待办**:
- [ ] 待完成任务 1: ___________
- [ ] 待完成任务 2: ___________
- [ ] 优先处理：___________

**如无待办**:
- [ ] 询问主人："今天有什么任务？"

---

## 🚫 禁止行为

- [ ] ❌ 不读 SOUL.md 就开始
- [ ] ❌ 不读核心规则卡片
- [ ] ❌ 不读 L1 日志
- [ ] ❌ 不检查 Token 状态
- [ ] ❌ 不确认待办就行动

  - 中断记录

- [ ] 确认无遗留问题
- [ ] 告知主人会话状态

## 🎯 常见问题

### 【Q: 为什么要读这么多文档？】
**A**: 
- SOUL.md = 我是谁（人格）
- USER.md = 为谁服务（主人）
- 核心规则 = 怎么做事（规则）
- MEMORY.md = 系统状态（环境）
- L1 = 当前进度（任务）

**不读的后果**:
- ❌ 忘记人格定位
- ❌ 违反核心规则
- ❌ 重复问主人信息
- ❌ 任务无法续接

### 【Q: 记不住怎么办？】
**A**: 
- 核心规则卡片 = 10 条铁律，反复阅读
- 检查清单 = 逐项检查，不易遗漏
- L1 日志 = 记录状态，下次续接

### 【Q: 时间太长怎么办？】
**A**: 
- 正常情况：4 分钟（必须）
- 紧急情况：1 分钟（最小化）
- 不要跳过，否则容易犯错
