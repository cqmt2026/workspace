## 一、编码错误预防

### 1.1 常见错误类型

| 错误类型 | 原因 | 预防措施 |
|----------|------|----------|
| 引号嵌套 | 字符串含特殊字符 | 使用write工具而非inline执行 |
| 路径编码 | Windows中文路径 | 统一用Python处理，避免PowerShell |
| 转义字符 | \n \t 混用 | 原始字符串 r"" 或双反斜杠 \\ |
| 缩进错误 | 混合tab/space | 统一使用4空格 |
| 括号不匹配 | 复杂表达式 | 分段编写，逐步验证 |

### 1.2 最佳实践

```python
# 错误示范
cmd = 'python -c "print(\"hello\")"'  # 多层引号嵌套

# 正确做法
# 1. 使用write工具创建脚本文件
# 2. 执行脚本文件
subprocess.run(['python', 'script.py'])
```

### 1.3 检查清单

执行前必查：
- [ ] 引号是否匹配
- [ ] 路径分隔符是否正确（/ vs \\）
- [ ] 中文字符是否导致编码问题
- [ ] 特殊字符是否需要转义
- [ ] 命令长度是否超过限制

## 二、工具选择优化

### 2.1 工具选择决策树

```
需要执行命令？
├─ 简单命令（1行）→ exec
├─ 复杂脚本（多行）→ write + exec
├─ 需要交互 → exec (pty=true)
└─ 后台任务 → exec (background=true)

需要修改文件？
├─ 小改动（<5行）→ edit
├─ 大改动/新建 → write
└─ 不确定内容 → read + edit/write

需要读取文件？
├─ 小文件（<50KB）→ read
├─ 大文件 → read (offset/limit)
└─ 查找内容 → exec (grep/findstr)
```

### 2.2 工具对比表

| 场景 | 推荐工具 | 原因 |
|------|----------|------|
| 创建新文件 | write | 一次性写入，避免追加错误 |
| 修改现有文件 | edit | 精确替换，保留其余内容 |
| 执行系统命令 | exec | 直接调用，无需文件 |
| 长命令/复杂脚本 | write + exec | 避免编码和转义问题 |
| 调试/测试 | exec (pty=true) | 交互式终端 |

### 2.3 避免的陷阱

1. **不要在exec中写复杂Python代码**
   - 错误：`python -c "complex_code_with_quotes"`
   - 正确：write script.py → python script.py

2. **不要混用路径分隔符**
   - 错误：`C:\Users\name\file` (在Python字符串中)
   - 正确：`r'C:\Users\name\file'` 或 `'C:/Users/name/file'`

3. **不要假设命令存在**
   - 先检查：`Test-Path` 或 `os.path.exists()`
   - 或使用 `-ErrorAction SilentlyContinue`

## 三、长程规划能力

### 3.1 任务分解框架

对于复杂任务，执行前必须：

```
1. 明确目标
   - 最终产出是什么？
   - 验收标准是什么？

2. 分解步骤
   - 拆分为独立子任务
   - 确定依赖关系
   - 估算每个步骤耗时

3. 识别风险
   - 哪些步骤可能失败？
   - 是否有外部依赖？
   - 需要什么权限？

4. 制定备选方案
   - 主方案失败怎么办？
   - 有无简化方案？
   - 何时放弃？

5. 设置检查点
   - 每步完成后验证
   - 关键节点汇报
   - 异常时止损
```

### 3.2 30分钟断点规则

- 预估超过30分钟的任务，必须先给用户看步骤分解
- 得到确认后再执行
- 每10分钟汇报一次进度
- 30分钟未达预期结果，必须切换方案或请示

### 3.3 任务状态追踪

创建任务时记录：
```json
{
  "task_id": "unique_id",
  "description": "任务描述",
  "steps": ["步骤1", "步骤2", "步骤3"],
  "current_step": 0,
  "status": "running",
  "created_at": "2026-10-12T22:00:00",
  "updated_at": "2026-10-12T22:05:00",
  "blockers": []
}
```

## 四、执行前检查流程

### 4.1 标准流程

```
收到任务
    ↓
[第一性原理拆解] 真正的需求是什么？
    ↓
[风险评估] 有什么潜在问题？
    ↓
[工具选择] 用什么工具最高效？
    ↓
[检查清单] 路径/依赖/权限是否满足？
    ↓
[执行] 执行并监控
    ↓
[验证] 检查结果是否符合预期
    ↓
[汇报] 输出结果+下一步建议
```

### 4.2 自检问题

执行前问自己：
1. 我真的理解需求了吗？
2. 有没有更简单的方法？
3. 这个操作有风险吗？
4. 如果失败了怎么恢复？
5. 用户需要知道什么？

## 五、持续改进机制

- 根本原因

### 5.2 模式沉淀

- 脚本模板
- 检查清单

### 5.3 定期复盘

每周回顾：
- 本周犯了多少错误？
- 哪些错误可以避免？
- 工具选择是否最优？
- 规划是否合理？

## 六、今日教训

### 6.1 编码错误
- **问题**：多次因引号嵌套导致SyntaxError
- **根因**：在exec中写复杂Python代码
- **解决**：复杂脚本用write工具创建文件

### 6.2 工具选择
- **问题**：powershell命令混用导致编码问题
- **根因**：未统一使用Python处理中文路径
- **解决**：Windows中文环境统一用Python

### 6.3 长程规划
- **问题**：多步骤任务执行中途才发现配置丢失
- **根因**：未在执行前检查依赖状态
- **解决**：建立执行前检查清单
