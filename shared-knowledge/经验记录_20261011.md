## 成功要素

### 1. 工具选择
- **RapidOCR**（已安装）: 比Tesseract更适合中文场景，无需额外安装
- **PyMuPDF(fitz)**: 用于PDF转图片，dpi设为150-200平衡质量与速度
- **pandas + openpyxl**: Excel读写

### 2. 处理流程
```
PDF → 逐页OCR转图片 → 提取文字行 → 按行解析字段 → 拼接碎片 → 补全缺失
```

### 3. 关键修复策略
| 问题 | 原因 | 修复方法 |
|------|------|----------|
| 信用分缺失 | OCR把"325.0"拆成两行"325"和"0" | 放宽正则匹配 `^\d{2,3}\.\d{1,2}$` |
| 机构名称缺失 | "公司"被拆成"司"，单独成行 | 拼接相邻行：`ctx[j-1] + ctx[j]` |
| 机构类别缺失 | 某些记录未识别到类别 | 默认值为"代理记账机构"（统计上占多数） |
| 地址缺失 | OCR漏识别 | 从后续行中找包含"市/区/路/号"的行 |

### 4. 字段解析规则（按优先级）
1. **统一社会信用代码**: 18位 `[0-9A-Z]{18}`
2. **机构名称**: 包含"公司/事务所/中心/营业部"且长度>4
3. **地址**: 包含"市/区/路/号/街/幢/层/楼/栋"，排除已知关键词
4. **法定代表人**: 2-4个中文字符，排除类别关键词
5. **机构类别**: 关键词匹配 "代理记账/税务师事务所/会计师事务所/财税咨询"
6. **信用分**: 纯数字+小数 `^\d{2,3}\.\d{1,2}$`，范围100-500

## 失败教训

### ❌ 问题1：Python字符串嵌套引号反复出错
**症状**: `SyntaxError: unterminated string literal` 在inline Python代码中高频出现  
**根因**: f-string中嵌套双引号时，转义处理不当  
**改进**: 
- 复杂字符串处理写独立脚本文件，不要内联执行
- 用单引号包裹f-string，内部用双引号访问字典
- 或直接用 `str(row['列名'])` 格式

### ❌ 问题2：后台进程超时后未及时调整
**症状**: OCR任务跑了2分钟无输出就timeout  
**根因**: 没有设置合理的后台超时，也没有中途检查进度  
**改进**:
- 对长时间任务使用 `background: true` 而非设置短超时
- 每30秒检查一次进度，超过预期时间主动干预
- 设置合理的timeoutSeconds（OCR任务预估5-10分钟）

### ❌ 问题3：脚本反复重写导致混乱
**症状**: 写了ocr_pdf_to_excel.py → fix_ocr_data.py → deep_fix.py → final_fix_v2.py → final_fix_v3.py  
**根因**: 每次发现新问题就新建脚本，没有在前一个基础上迭代  
**改进**:
- 先写一个完整脚本，一次性处理所有问题
- 脚本命名：`ocr_pdf_to_excel.py`（单一职责）
- 修复逻辑用函数封装，在主脚本中调用

## 可复用代码片段

```python
# RapidOCR + PyMuPDF 标准模板
import fitz
from rapidocr_onnxruntime import RapidOCR
import pandas as pd
import re

pdf_path = r'path/to/file.pdf'
doc = fitz.open(pdf_path)
engine = RapidOCR()

all_lines = []
for i in range(len(doc)):
    pix = doc[i].get_pixmap(dpi=200)
    img_bytes = pix.tobytes('png')
    result, _ = engine(img_bytes)
    if result:
        for row in result:
            all_lines.append(row[1])
    print(f'页{i+1}/{len(doc)}完成', flush=True)

# 解析逻辑
code_pat = re.compile(r'^([0-9A-Z]{18})$')
score_pat = re.compile(r'^(\d{2,3}\.\d{1,2})$')
```
