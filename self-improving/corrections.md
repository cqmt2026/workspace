## 教训1：replace脚本同一关键词多次匹配

### 背景
批量给章节添加爽点关键词时用了：
```python
content = content.replace('**【本章完】**', add + '\n\n**【本章完】**')
```

### 问题
多次运行或关键词重叠导致同一内容被匹配多次，结果：
- 第2-10章出现大量重复段落
- 最严重的第7章重复5+处
- 第4章"华强北之行"整段重复3次

### 根因
Python的str.replace()会替换所有匹配项，不检查是否已存在

### 正确做法
```python
if add not in content:  # 先检查是否存在
    content = content.replace(marker, add + '\n\n' + marker)
```

### 验证
每章写完立即执行：
```python
# 重复行检查
seen = {}
for line in content.split('\n'):
    if line.strip() in seen: print(f'DUP: {line[:50]}')
    seen[line.strip()] = 1
```

## 教训2：exec -c命令行处理中文字符串

### 问题
PowerShell中`python -c "中文"`触发编码错误

### 方案
1. 用脚本文件`python script.py`执行
2. 绕开PowerShell用Python内置`exec(open(path).read())`

### 示例
```bash
# 错
python -c "content.replace('老段', '新段')"  # 报错

# 对
python script.py  # 先写入文件再执行
```

## 教训3：子Agent失败率很高

### 观察
- 子Agent启动快但经常runtimeMs=0立即失败
- 成功率和任务复杂度正相关
- 重复内容处理、文本替换类任务失败率高

### 方案
- 关键验收必须主会话自己做
- 子Agent只做批量框架+初步验证
- 最终质量由主会话检查

## 教训6：自我进化系统不是自动运行的

### 背景
2026-05-05对话总结时发现：memory.md和corrections.md更新时间停在4天前，今天大量工作没被记录。

### 问题分析
| 机制 | 期望 | 现实 |
|------|------|------|
| 纠正自动捕获 | 被纠正时立即写入 | 依赖我手动写 |
| 新学习自动记录 | 学到新认知立即写入 | 依赖我手动写 |
| PREFERENCES同步 | 每30分钟cron | 已实现 |

### 根因
自动记录新学习和自动纠正捕获不是cron任务，是对话中的实时行为。高强度工作时优先完成任务，延迟了学习记录。

### 纠正措施
1. 每次纠正后立即写入，不拖延
2. 每次学到新认知立即写入memory.md
3. 保持PREFERENCES每30分钟同步
