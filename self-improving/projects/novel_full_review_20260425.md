## 一、作品定位问题

### 1.1 题材定位模糊

**现状**: 作品定位"都市+专业流+鉴宝打脸"，但"鉴房"不是"鉴宝"——读者期待的是专业碾压爽感，但前三章没有兑现。

**具体表现**:
- 第1章全章写排队买楼，主角身份和能力都没亮相
- 第2章才出现"首席验房师被开除"，铺垫拖沓
- 前三章配角方磊的戏份超过主角，喧宾夺主

**教训**:
```
[小说创作] 题材定位必须在第一章第一句话就兑现
[小说创作] 主角的核心能力必须在第一章就展示
[小说创作] 配角戏份不超过主角20%
```

### 1.2 开篇公式缺失

**现状**: 没有遵循"前三章法则"——主角身份、核心能力、主要矛盾，前三章必须全部亮相。

**对比数据**:
- 爆款都市文第1章公式：主角困境/危机→立刻专业/打脸
- 《鉴城师》第1章：环境描写→配角对话→身份揭露拖到结尾

**教训**:
```
[小说创作] 前三章必须包含：主角是谁、主角会什么、主角要对抗什么
[小说创作] 第一句话就要有冲突或悬念，不能用环境描写开头
[小说创作] 都市专业流：主角出场即秀专业技能
```

## 二、创作管线问题

### 2.1 大纲执行不到位（最严重）

**现状**: 大纲是执行版圣经，但实际上每次都是"先写再对照"，导致71-80章严重偏离大纲，最终返工。

**具体表现**:
- 项目二71-80章实际内容与大纲要求完全不同
- 71章大纲要求"连片改造"，实际写成了"行业标准制定"
- 78章大纲要求"城中村改造"，实际写了"求婚"
- 返工浪费了大量时间

**根本原因**:
1. 创作时没有对照大纲检查
2. 自我发挥，偏离主线
3. 子agent不理解大纲的优先级

**教训**:
```
[小说创作/强制] 大纲是圣经，写完必须对照检查，不对照不归档
[小说创作/强制] 子agent任务必须附带章节大纲内容
[小说创作/强制] 每章创作前必须读本章大纲要点
```

### 2.2 字数管理失控

**现状**: 子agent处理的章节经常字数不足（1100-1700字），需要反复扩充，效率极低。

**具体表现**:
- 72-73章：子agent只完成了字数达标
- 74-80章：子agent超时，只写了一半字数
- 每次扩充都要手动返工5-8次

**根本原因**:
1. 一次生成内容过长，超出token限制
2. 没有分批生成+字数验证的自动化流程

**教训**:
```
[小说创作/强制] 单次生成不超过2000字
[小说创作/强制] 生成后立即验证字数，不达标不保存
[小说创作/强制] 字数不够再扩充，不一次生成
```

### 2.3 标题管理混乱

**现状**: 标题和内容不一致，多次出现标题已改但内容没改、内容已改但标题没改的情况。

**具体表现**:
- 第73章归档了2个不同标题版本
- 第92章归档了4个不同标题版本
- 子agent生成的章节标题和之前优化的标题混在一起

**根本原因**:
1. 没有统一的标题管理机制
2. 文件名和内容标题不同步
3. 多版本并存，没有唯一版本意识

**教训**:
```
[小说创作/强制] 一个章节只有一个版本，归档后不保留旧版本
[小说创作/强制] 每次修改后重新归档，旧版本删除
[小说创作/强制] 标题格式：多样化，避免"：标签"格式
```

## 三、系统性问题

### 3.1 规则制定了但不执行

**现状**: MEMORY.md里写了很多规则（"V7.0质量检查"、"强制调用大纲"），但每次遇到压力就跳过。

**根本原因**:
1. 任务优先于流程——先完成再说
2. 没有强制执行机制——规则只是"建议"
3. 执行偏差不记录——同样的错误反复犯

**教训**:
```
[小说创作/强制] 规则就是规则，不执行=违反，违反记入corrections
[小说创作/强制] 每日创作前检查：今日是否跳过任何规则？
[MEMORY] 规则执行率纳入自检清单
```

### 3.2 子agent任务不规范

**现状**: 子agent任务经常超时、字数不达标、内容偏离大纲。

**具体表现**:
- 72-80章子agent任务超时4次
- 子agent返回结果没有验证就接受
- 同一章节出现多个不同版本

**教训**:
```
[小说创作/强制] 子agent任务必须包含：(1)章节大纲内容 (2)字数标准 (3)验证方法
[小说创作/强制] 子agent完成后必须验证，不达标不接收
[小说创作/强制] 超时的子agent立即补充任务，不等待
```

## 四、番茄平台运营问题

### 4.1 前三章开篇没有兑现题材承诺

**问题**: 读者划3章就走了，平台判定"内容不吸引"，减少推荐。

**具体数据**: 阅读人数18（+260%但绝对值低）、追更0、评分0——说明流量进来了但留不住。

**教训**:
```
[自媒体运营] 前三章法则：主角身份+核心能力+主要矛盾必须前三章全亮相
[自媒体运营] 第一句话就要有冲突或悬念
[自媒体运营] 每章结尾必须有钩子，让读者想点下一章
```

### 4.2 平台推荐机制理解不足

**问题**: 番茄靠"读完率+追更率"决定推荐量，光日更不够。

**教训**:
```
[自媒体运营] 读完率=读者划到第几章，决定平台推多少流量
[自媒体运营] 追更率=读者愿不愿意等更新，决定推荐权重
[自媒体运营] 前三章是生死线，决定读者留不留
```

## 五、核心总结

### 五个最需要改进的地方

| 优先级 | 问题 | 改进 |
|--------|------|------|
| **P0** | 大纲执行不到位 | 写完必对照，不对照不归档 |
| **P0** | 前三章开篇公式缺失 | 第一句话就有冲突，主角能力立即亮相 |
| **P1** | 字数验证没有前置 | 先生成2000字→验证→不够再扩 |
| **P1** | 标题管理混乱 | 一个章节只有一个版本 |
| **P2** | 规则制定不执行 | 不执行=违反，记入corrections |

### 一个最核心的认知

> **写小说不是"先完成再完美"，是"先设计再施工"**  
> **大纲=设计图纸，质量检查=施工验收，不按图纸施工必然返工**
